# 架构决策与实际状态

这里区分已落地的实现和仍未实现的设计目标，避免把计划误写成现状。

## ADR-001：核心逻辑采用 Pure Go

- **状态**：核心包采用 Pure Go；客户端窗口目前仅支持 Windows。
- **决定**：协议、NBT、世界存储、模拟和软件光栅器使用 Go 标准工具链，不依赖 CGO。
- **实际限制**：尚无跨平台原生图形窗口或 GPU 渲染后端；`go build ./...` 成功不代表各平台交互运行已验证。

## ADR-002：单仓库内共享模拟与世界代码

- **状态**：部分实现。
- **决定**：客户端和专用服务端共用 `pkg/sim`、`pkg/world`。
- **实际限制**：单人模式直接运行客户端本地 Engine，不是原版 Integrated Server 的网络架构；多人包同步仅为子集，行为没有证明一致。

## ADR-003：模拟时钟与并发边界

- **状态**：部分实现，仍需真实运行时验证。
- **决定**：服务端使用 50ms 定时循环；客户端本地模拟在渲染主循环按 50ms 累计步进，以串行访问实体和绘制共享状态。
- **实际限制**：网络接收和存档等仍有并发路径；尚未使用 race detector 完成检查；区块生成/网格构建没有通用有界工作池或版本令牌。

## ADR-004：Minecraft 数据格式与协议探索

- **状态**：不承诺原版网络兼容。
- **决定**：保留 VarInt、NBT、MCA 等兼容格式的实现探索，并限制网络帧最大为 2 MiB。
- **实际限制**：登录/配置/游戏包集合、字段编码、区块与实体同步、资源数据和数据版本转换没有完整实现或原版互操作证据。代码中的版本常量不能作为兼容性证明。
