# 项目状态

最后核对：2026-11-23。项目仍是进行中的 Go 体素沙盒原型，**没有达到 Minecraft Java Edition 或 Horizon 的功能、画面、协议或生态等价**。此前里程碑中“100% 通过”“完全对齐”等说法没有足够的可重复证据，已从状态记录中移除。

## 本轮已落地

- 客户端世界模拟改为渲染主线程 50ms 固定步进，避免客户端 Tick 与渲染并发访问实体状态。
- 方块变更和初始区块的网格都由单个后台工作线程按分区去重重建，待处理队列上限 128，完成后校验版本再发布，避免输入/网络回调和渲染线程等待网格计算。
- 网格和区块流送队列都会检查正在运行的同键任务，避免窗口线程在 worker 计算期间重复排队同一分区；网格扫描只挑选少量新任务，队列达到 128 项时停止继续增长。
- 卸载区块时同步提升其 section 与四邻 section 修订号并清除旧网格；网格任务完成后清理未驻留且无待处理/运行任务的修订项，避免长距离探索导致修订表无限积累。
- 区块网格缓存使用世界代次和分区修订号，丢弃跨维度/旧方块状态的迟到构建结果，避免旧网格覆盖新状态。
- 方块修改统一校验世界高度、原版水平边界及非负方块状态；客户端/服务端网络入口在分配区块、加入变更表或重建网格前拒绝越界坐标，避免畸形方块包造成无界区块分配。
- Section 本地块/生物群系索引严格校验各轴范围；Chunk 读写确认绝对坐标属于自身区块，模拟引擎也拒绝把位置不匹配的区块安装到另一坐标，避免低四位掩码导致串列读写。
- 服务端进一步要求联网玩家方块修改位于自身六格内且方块 ID 可放置；移动包拒绝 NaN/Inf、越界坐标和非法俯仰角，避免任意远程写入及异常浮点状态污染模拟。
- 修正可放置方块白名单遗漏铁块、金块和钻石块的问题，避免客户端放置成功后被服务器静默拒绝，已由真实双客户端同步用例覆盖。
- 客户端验证服务端远程玩家位置包中的有限数、世界边界和俯仰角；畸形包会记录并断开连接，不进入实体渲染数据。
- 客户端同步和后台网格生成都通过带堆栈日志的恢复边界保护；单个异常分区退化为空网格并继续运行。区块/section/调色板访问对缺失或残缺内部数据安全返回空气/默认值，存档序列化也会补齐缺失 section。
- 客户端 panic 与主循环卡顿记录按时间追加到 crash.log，并用互斥锁串行写入，避免新记录覆盖之前的现场信息。
- 原生窗口的完整 `RenderFrame` 外围增加 panic 恢复：首次失败记录堆栈到 crash.log，连续失败达到 3 帧时请求关闭窗口，让已有退出收尾流程保存世界；成功渲染一帧后重置连续失败计数。尚未在真实窗口中触发验证，且窗口呈现调用自身的驱动级故障不一定能由此恢复。
- Win32 按键/鼠标窗口过程捕获到回调 panic 时，除恢复消息循环外还会把消息号、panic 值和堆栈交给客户端写入 crash.log。
- Windows GDI 呈现 framebuffer 前校验窗口/纹理宽高及颜色切片容量，避免把尺寸不匹配的 Go 像素缓冲指针交给 `StretchDIBits`。
- MCA 区域写入检查短写；新 chunk 数据先完整写入并同步，再提交位置表，位置表提交或同步失败时尝试恢复旧位置表，降低磁盘写入错误导致旧 chunk 失联的风险；相同 NBT 的重复写入只更新时间戳，避免无变化存档持续扩张。
- 软件渲染阶段逐三角形校验索引范围并跳过无效索引；光栅器拒绝 NaN/Inf、非正深度、超大投影坐标和非法光照系数，避免异常网格引发数值污染或切片越界 panic；线段先裁剪到 framebuffer，再运行整数光栅循环，避免远端端点造成溢出或超长遍历卡住窗口。
- 外置 PNG 纹理在读盘、解码配置和像素分配前限制编码体积及最大像素数；原始纹理采样和绘制会拒绝与宽高不匹配的像素缓冲，并跳过 NaN UV，避免异常资源导致超量分配或切片越界。
- 窗口尺寸变化时复用 framebuffer 现有容量，尺寸稳定时不分配；减少拖动缩放期间反复创建颜色/深度缓冲产生的 GC 和内存峰值。
- 客户端区块磁盘读取、地形生成、远区块卸载与同步落盘统一移到单后台队列执行；队列限制待生成区块数，任务绑定维度和世界代次，避免窗口线程因地形生成或磁盘写入长时间无响应。
- 世界选择界面扫描存档目录及读取各个 `level.dat` 改由后台执行；窗口主线程只轮询并接收结果，扫描期间显示独立的“正在读取存档”状态。
- 原生窗口中新建/载入单人世界改由后台初始化；消息泵显示加载画面，期间拒绝游戏输入，成功后由窗口主线程恢复鼠标捕获，失败回到菜单并提示查看日志；初始化 panic 会写 crash.log 并尝试清理半开的世界；窗口关闭会等待初始化结束再做存档收尾。
- 统一退出收尾也会关闭“SaveManager 已创建、Engine 尚未建立”的半初始化存档句柄，避免启动异常后占用区域文件。
- 区块流送失败冷却缓存每 10 秒清理过期/旧世界代次条目，避免长时间探索大量损坏区域时失败坐标表无限增长。
- 安全出生点候选改为从出生点附近的区块环依次扫描，避免随机尝试大量坐标并重复触发区块生成；同步生成后直接安装到指定维度，避免重复磁盘读取或把重生区块放错维度。
- 地形生成结束后清除生成阶段积累的 `ModifiedBlocks` 差异表并标记区块为干净状态；自然地形只保存在调色板数据里，避免每个自然方块再占一份坐标映射和存档 NBT 记录。
- 退出世界时先提升世界代次取消过期任务，并等待区块流送队列清空，再停止模拟和执行最终存档，避免后台生成在最终保存后重新安装未落盘区块。
- 单人游戏每 60 秒在后台保存玩家/世界元数据和脏区块；退出时等待后台保存结束。区块逐个做受模拟锁保护的深拷贝快照，再释放全局模拟锁写盘；写盘后仅在区块修订号未变化时清除脏标记，避免大批脏区块同时复制造成内存峰值。
- 退出到标题一旦开始就不再创建自动存档任务，避免同一 UI 帧中 WaitGroup.Wait 与新的 Add 并发。
- 后台自动存档 goroutine 也有独立 panic 恢复与堆栈记录，避免后台写盘异常直接结束整个 Go 进程。
- 区块网格读取只访问已驻留内存的数据，不会在渲染阶段触发懒加载磁盘读取；异步载入后使本列和四周邻列受影响网格失效，防止临时空气结果留下缺面。
- 模拟引擎的懒加载区块读取在获取/安装存档数据期间不持有全局模拟锁；客户端碰撞、选块、渲染等实时路径改用仅内存读取，避免后台 MCA 读盘阻塞主线程。
- 新建世界和切维度只预热一轮区块，其余工作交给逐帧流式加载，避免在窗口消息回调中连续生成/网格化 25 轮。
- 客户端离开世界时先关闭网络连接并等待接收循环退出，再保存和释放世界。
- GUI 窗口关闭、命令行退出都会执行存档收尾。
- 标题界面的 Esc/Q/退出按钮现在只请求原生窗口关闭，让消息泵正常退出并运行已注册的收尾 defer；不再用 `os.Exit` 直接跳过清理。
- 原生窗口退出时先销毁窗口，再执行最终区块/玩家存档；watchdog 在最终保存期间保持运行并可记录卡住时的 goroutine 堆栈，避免慢磁盘保存期间仍留着未响应窗口。
- 暂停菜单/死亡界面的“退出到标题”改为后台保存：暂停模拟、释放鼠标捕获，窗口主循环继续显示保存提示并泵消息；保存结束后切回标题。保存中关闭窗口会等待该保存任务结束后再执行幂等收尾。
- 最终区块、玩家元数据或存储关闭失败会汇总写入 crash.log；回到标题后显示存档失败提示，不再只在后台输出日志。
- 退出时关闭所有维度的区域文件；服务端停止时等待会话处理 goroutine 结束后再保存。
- 网络帧读取和写入限制为 2 MiB，拒绝超大长度，避免对端数据触发失控内存分配。
- NBT 解码限制输入字节、数组、列表、总标签数和嵌套深度，拒绝负长度与异常结构。
- gzip/zlib NBT 会受限地读至流末尾以验证压缩校验；未压缩区块拒绝根标签后的尾随数据。
- gzip/zlib NBT 写入会传播压缩器关闭错误，防止校验尾部写失败仍被报告为成功。
- Nether/End 存储目录初始化失败会显式上报；客户端和服务端停止启用存档，避免维度区块回退写入主世界目录。
- 存档恢复并继续昼夜时间和累计世界 Tick。
- 读取玩家存档时校验坐标、游戏模式、生命/饥饿值、视角及物品槽位，异常坐标回退到安全出生点。
- 背包添加/移除接口拒绝 nil 接收者和非正移除数量，避免负数移除把库存数量反向增加。
- 存档的世界出生点始终从玩家实体的 `SpawnPos` 保存，不再随着退出时玩家所处坐标漂移；重生和死亡退出优先复用已验证的出生点，避免 UI 回调中再次同步扫描/生成出生区块。
- MCA 区块读写校验区域位置、扇区边界、重叠分配和可编码长度；新区域头、数据负载及索引头均同步写盘。区块替换使用写时复制，并在校验整个索引表后复用空闲扇区；旧负载保留到新负载落盘并切换索引后，降低中途退出造成的数据损坏风险。
- 载入 MCA 区块时校验 NBT 内坐标与区域槽位坐标一致，拒绝把错位负载映射到错误世界坐标。
- 新建世界使用独占目录创建；若目录名已存在则生成带序号的新目录，避免覆盖已有世界存档。
- Windows 上替换 `level.dat` 使用带替换和写穿标志的 `MoveFileExW`，避免目标文件已存在时普通 `os.Rename` 无法更新元数据。
- 新世界首次 `level.dat` 写入失败时中止进入世界并关闭存储，避免把无法持久化的世界当作正常创建成功。
- SaveManager 关闭后拒绝新的读写和打开区域文件请求。
- MCA 空槽通过专用 `ErrChunkNotFound` 与损坏/磁盘错误区分；客户端流送、出生点、服务端加载和方块写入不会把不可读区块当作新地形覆盖，磁盘加载移出全局模拟锁；`SetBlockChecked` 让挖掘/放置/服务端变更在确认写入后才发奖励或记录变更；客户端读盘或地形生成失败会记录并按世界代次冷却 30 秒，避免逐帧重试。
- NBT 区块解码现在拒绝重复/越界 section、错误类型或长度的方块/生物群系数组、负状态 ID，以及越界到其他区块或超过容量的 `ModifiedBlocks`；解析失败会阻止损坏数据进入后续存档覆盖。
- 服务端等待会话 goroutine 结束后再存档，并隔离单个客户端会话的 panic。
- 服务端会话写包设置 5 秒写期限；连接写入失败时主动关闭 socket，释放读循环并让停服收尾可以清理玩家、继续保存世界。
- 服务端会话状态、玩家 ID、名称和 UUID 统一经会话互斥锁访问；连接关闭不需要等待写线程锁，可打断阻塞写入并继续玩家清理。
- 每个服务端会话使用容量 256 的有界出站队列和独立写循环；慢客户端写超时或队列积满时断开该连接，不阻塞全服广播。
- 新玩家登录时先复制已修改方块和会话列表再释放服务器锁，避免初始区块状态同步期间的网络写入阻塞整个服务端。
- 梯子网格按相邻支撑方块朝向生成，避免被绘制为交叉植物面。
- 切换维度时用“维度 + 坐标”作为区块任务键，将旧维度存档卸载和新维度加载放入后台队列；维度切换与缓存代次切换在同一临界区完成，避免主线程同步写盘、同坐标任务互相覆盖或旧区块迟到驻留。
- 修正项目说明中的兼容性夸大描述。

### P1：地图与渲染

- 当前是自制软件光栅器和程序化材质，不是原版渲染管线。光照、阴影、透明物排序、液体、植被、远景、动画和性能表现都仍需逐项对照。
- 对用户报告的闪烁、缺面、模糊贴图和区块接缝建立可复现步骤，再按渲染阶段修正。
- 检查不同窗口尺寸、高 DPI、全屏切换、极端长宽比和低性能机器上的内存及帧时间。

### P2：方块、物品、配方、实体与进度

- 方块/物品注册表、方块状态、工具规则、掉落表、配方、药水、附魔、盔甲和容器内容远未证明覆盖原版。
- 进度目前只是少量本地触发项，尚非原版完整进度树、条件、奖励和同步实现。
- 生物种类、寻路、战斗、生成规则、掉落、动画与行为都需要扩展和实机核对。

### P3：协议、服务端与生态

- 当前网络实现是自定义子集；不能据现有包结构或版本号宣称可加入原版 Java 服务器。
- 登录、配置、区块数据、实体同步、聊天、命令、权限、插件/模组接口和版本兼容性尚未完整实现或验证。
- 与 Horizon 的行为、资源格式、存档兼容性及性能差异尚无完整基准。

### P4：界面与平台

- 当前 UI 是自绘近似界面，菜单布局、字体、动效、缩放、无障碍选项和输入体验与原版仍有明显差异。
- 原生游戏窗口目前使用 Windows API；跨平台图形窗口尚未完成。
- 不以复制受版权保护的原版贴图、音频或品牌界面作为目标；需要使用可合法分发的自制或兼容资源。

## 工作规则

每批改动先解决可复现的问题，执行构建与静态检查，再推送到 `main`。未运行的验证、未复现的故障和仍缺失的玩法必须继续标为未完成。
